# 《分道扬镳》AI 数值测试与验收文档

> 版本：v0.4（同步 3 秒单向结盟申请等待期验收）
> 定位：功能实现后，由 Agent 通过 Unity MCP 控制编辑器，投放两个 AI 玩家进行自动化数值测试、调试与验收
> 原则：验收以数据、日志和可复现实验为准；视频仅用于人工复盘，不作为验收依据

---

## 一、目标与范围

1. 全自动跑“双 AI 对局”，对核心数值做批量扫描与回归。
2. 找出重大数值问题（永远该杀/永远不该杀、结盟必胜、心争夺尾刀化、囤塔无敌、双输率过高等）。
3. 输出最佳数值推荐包：每个参数给推荐值、可选区间、灵敏度、置信度与风险。
4. 每次调整后重新跑核心场景，防止改一个参数破坏另一个系统。

**测试阶段划分**

| 阶段 | 内容 | 进入下一阶段条件 |
| --- | --- | --- |
| 阶段零：AI 稳定性 | 跑 AI 质量测试用例，修复 AI 行为问题 | 有效局率 ≥ 90%，无卡死/寻路高频失败 |
| 阶段一：数值扫描 | 双 AI 参数扫描与回归 | 推荐包 + 异常清单产出 |
| 阶段二：手感微调 | 真人抽测 + 自动化回归 | 手感验收通过 |

**测试对象（当前 v1.x 规则）**

- 囚徒困境引擎：单位时间共享击杀权重超阈值 → Boss 提前苏醒（自然怪 1 / 幽灵 2 / 恶魔之子 10；示例阈值 100 待实测，形态不随超出增强）；玩家击杀权重 3-5 倍待换算；个人权重超共享阈值 65% → 恶魔分身。
- Boss 战：Boss 战力压制判断、感知战力浮动、生命低于 30% 时转击杀、Boss 主动结盟申请 60 秒冷却、Weak / Normal 求生判断与退出。
- 结盟：弱者+Boss（15-20s）、玩家+玩家（30-45s）、2-3 秒确认、3 秒单向申请等待期、玩家间主动申请 120 秒冷却、Boss 结盟后 10 秒玩家间封锁、翻脸 debuff。
- 心争夺：10 秒拾取读条、打断/回退/重置、淘汰掉落、交付过场。
- 塔与囤塔：战力构成、结盟期间锁定、结盟后解锁、4 座配额 / 2 座保底、囤塔翻盘。
- 死亡与胜负：Boss 苏醒前玩家死亡先进入回魂契约；成功回魂则恢复参与，未回魂 / 回魂机会耗尽 / Boss 苏醒后出局；系统分别结算每名玩家的胜负，若双方均失败，统计层记录双输。

## 二、前置条件与环境

| 项 | 要求 |
| --- | --- |
| Unity 编辑器 | 打开测试场景，MCP 服务已连接（`com.anklebreaker.unity-mcp`） |
| MCP 工具 | Agent 先读取实际暴露的工具清单，工具名以清单为准 |
| AI 玩家 | 复用 `PlayerBehaviourModel` 角色卡（Guardian/Hunter/Scholar/Veteran/Rookie）与 `MonsterBehaviourModel` |
| 测试人格 | 可注入：合作型、军备型、背叛型、结盟型、逃跑型、风筝型 |
| 确定性 | 固定随机种子、固定初始资源、固定初始点位 |
| 运行方式 | 优先编辑器内运行；可行时增加 Batch Mode 固定步进 |

> 若 MCP 未连接或场景缺失，Agent 应暂停并请求人工启动，不自行猜测。

## 三、测试方法论

### 3.1 确定性

- 每局记录随机种子，同参数同种子结果必须可复现。
- 关键局使用固定种子组（默认 30-50 局/组），避免单局噪声。
- 浮点波动判定提供调试开关：`forceJudgeResult` / `fixedRandomSeed`，测试用确定值，发布用波动。

### 3.2 快照与事件

- 状态快照：每 0.5-1 秒记录双方血量、战力、击杀数、Boss 形态/强化层、结盟状态、心位置、塔数量、海平面水位，落 JSON/CSV。
- 事件日志：Boss 提前苏醒、求生开始/结束、结盟申请/成功/被拒、翻脸、心掉落/拾取/打断、Boss 击杀、出局、双方分别结算失败（统计层双输）、AI 卡死，全部带时间戳。

### 3.3 核心指标

| 指标 | 说明 |
| --- | --- |
| 胜负分布 | 一方胜 / 双输 / 未完成占比 |
| 双输率 | 双方都未获胜的对局占比，硬指标上限建议 15-20% |
| 对局时长 | 目标 22-25 分钟（加速墙钟时间另计） |
| 结盟成功率 | 弱者+Boss 与玩家+玩家分别统计 |
| 背叛后胜率 | 翻脸方成功比例 |
| 心争夺抢断率 | 拾取被打断/被抢的比例 |
| 囤塔使用率 | 结盟后放塔风筝/翻盘使用占比 |
| 战力差相关性 | 战力高方实际胜率，验证“接近不代表一边倒” |
| 有效局率 | 通过运行有效性门禁的对局占比，硬指标建议 ≥ 90% |

### 3.4 目标函数

- 硬指标：有效局率 ≥ 90%、双输率 ≤ 上限、双方胜率 40-60%、时长 22-25 分钟、结盟成功率 ≤ 60%、心争夺非纯尾刀。
- 软指标：心争夺抢断率、背叛胜率、囤塔翻盘率，用于候选排序。
- 参数推荐输出 Top 3 组合，不锁死单一答案。

### 3.5 运行有效性门禁

每局结束先判定是否有效，无效局不计入统计、标记原因并进入复验队列：

- 任一方卡死超过阈值（如 10 秒无有效行为）→ 无效
- 寻路失败 / 进入不可达区域 → 无效
- 事件序列缺失（该提前苏醒没提前、该掉心没掉、该交付没交付）→ 无效
- 对局异常中断 / 超时 → 无效

有效局率 = 有效局 / 总执行局。有效局率低于 90% 时，先修复 AI 或环境问题，再继续数值扫描。

## 四、验收表

### 4.1 囚徒困境引擎

| 项目 | 测试方式 | 通过标准 |
| --- | --- | --- |
| 苏醒阈值 | 参数扫描 + 固定人格对局 | 阈值边界行为符合设计；“该不该杀”在不同局势答案不同 |
| 玩家击杀权重（3-5x） | 人工制造击杀局 | 击杀对手明显推 Boss，但不会让“打残”失去意义 |
| 收益曲线 | 对比战力增益 vs 提前苏醒代价 | 不存在“永远该杀”或“永远不该杀” |
| 提前苏醒预警 | 事件日志校验 | 提前苏醒前有预警且双方可见 |

### 4.2 Boss 判定

| 项目 | 测试方式 | 通过标准 |
| --- | --- | --- |
| 战力压制 | 构造 Boss 与两名玩家战力矩阵 | 两名玩家感知战力都低于 Boss 战力 70% 时不结盟 |
| 单人残局结盟 | 先淘汰一名玩家，再尝试申请 / 主动提议 / 保持已有结盟 | 存活玩家数为 1 时绝不结盟；拒绝申请、停止提议；已有结盟立即结束且不产生追杀仇恨 |
| Rage 计时 | 在同一 `gameTime`、不同 `encounterStartTime` 下运行 | `encounterTime = gameTime - 苏醒时间`；达到 480s 才进入 Rage |
| 阶段默认倍率 | 依次切换 Weak / Normal / Rage | 最大生命、攻击和攻击速度倍率为 0.6 / 1.0 / 2.0；移速、技能频率和仇恨倍率始终为 1.0 |
| 三类距离 | 分别构造获取、追击、攻击临界距离 | Acquire、Chase、Attack 独立配置；残血只改变 ChaseRange |
| Boss 普攻距离 | 默认配置下移动至攻击临界点 | `attackRange = 2m` 可被配置覆盖，与获取和追击距离独立 |
| 圣物接口 | Fake IRelicStateProvider 返回基础、衰减和版本变化 | Boss 只消费 relicHate，不保存日/月数值；版本变化触发目标刷新 |
| 感知浮动 | 同局面多种子统计 | 感知战力有 ±5% 波动，但整体趋势可预期 |
| 残血转击杀 | 弱者低血局 | Boss 选择击杀而非结盟 |
| 残血修正计算 | 目标生命比例取 30.0% / 29.9% / 20% / 10% / 9.9% | 30% 修正为 0；20% 为 1000；≤10% 封顶 2000，公式边界正确 |
| 残血追击范围 | 生命 29.9% / 30.0%，距离 20m / 40m / 40.1m | <30% 时有效追击距离 40m；≥30% 时回到 20m；>40m 立即终止残血追击 |
| 残血资格过滤 | 残血目标死亡、成为盟友、不可选或进入无效区域 | 立即从残血追击候选池移除，不继续追击 |
| Weak 求生进入 | Weak 且 20m 内非盟友玩家总生命 > Boss 当前生命 150% | 血量低于 `35% × 0.9-1.1` 时进入，逃跑并请求第一技能槽 slotId=1 |
| Normal 求生进入 | Normal 且 20m 内非盟友玩家总生命 > Boss 当前生命 200% | 只有血量低于 10% 时进入，逃跑并请求第一技能槽 slotId=1 |
| 状态竞争裁决 | Weak / Normal 同时满足求生和残血追击条件 | Weak 优先逃生；Normal 仅在 `<10%` 且敌我生命比 `>200%` 时逃生，否则优先残血追击；Rage 不逃生 |
| 求生敌人过滤 | 一名玩家与 Boss 结盟，另一名玩家进入 20m | 盟友不计入总生命，只有非盟友玩家参与判断 |
| 求生快照 | 5 秒周期内快速改变血量、距离和盟友关系 | 周期内不重算，下一快照才更新进入判断 |
| 求生退出 | Weak / Normal 恢复到 40% / 30% | 达到对应阈值立即结束，Rage 不进入 Survive |
| Survive 自动回血 | 进入 Survive 并持续受伤 | 调用 `IHealthService.EnterAutoRegen`，由 Health 按 Survive 配置回血；退出、Rage、死亡或 slot1 不可用时停止 |
| 求生槽位 Disabled | 进入求生条件成立，但 slot1 为 Disabled | 不进入 Survive；若已在 Survive 则立即退出；日志中无每帧 `TryRequestSlot(1)` |
| 求生槽位 Cooldown | 进入求生条件成立，slot1 处于 Cooldown | 可短暂逃跑等待；仅当 slot1 变为 Ready 时请求一次，不轮询 |
| 求生请求阻塞 | slot1 为 Ready，但当前存在不可打断动作锁 | 保留 pending 请求，动作锁释放后重试一次；日志中无每帧重复请求 |
| 求生超时兜底 | slot1 长期不可用或恢复失败，持续到 `maxSurviveDuration` | 强制退出 Survive，进入强制退出冷却，然后按 SeekAlliance / Engage / Chase 兜底；不得无限逃跑 |
| 求生阈值立即刷新 | 在 5 秒周期外让 Boss 首次跌破进入阈值或回到退出阈值 | 立即刷新 5 秒求生快照；满足条件立即进入，达到退出阈值立即结束 |
| 逃跑目标选择 | 多个非盟友分布在 Boss 不同方向并设置障碍 | 每秒评估候选点并通过 NavMesh 落点校验；目标位移 <2m 或评分优势 <0.15 时保持原目标 |
| 逃跑卡住判断 | Boss 被减速、绕障碍或横向滑动，1 秒有效路径进度低于阈值 | 按 `max(0.5m, 预期进度×25%)` 判定，不按总位移误判 |
| 逃跑无有效进度 | 候选点失效、PathPartial、路径 Pending 超时，累计 >2.5 秒 | 标记 noEscapePath，强制退出 Survive，不原地等待 slot1 CD |
| 死亡强制刷新 | 在 5 秒 / 10 秒周期外触发玩家淘汰或 Boss 死亡 | 先结束相关结盟并递增 allianceVersion，再立即刷新所有活动快照；同帧后续决策使用新快照 |
| Rage 行为 | Rage 且低血量、被围攻 | 不逃跑、不结盟、不进入回血姿态，只攻击、追击并请求 slot2/3；slot1 仅在连续 3 秒未命中敌对玩家时请求 |
| 技能槽请求 | 切换 Boss 状态与意图 | Boss 只输出 slotId 和状态原因，不依赖固定技能名 |
| 槽位替换 | 保持状态机不变，替换 slot2 / slot3 的 SkillCard | 行为请求序列不变，效果按新 SkillCard 执行 |
| 第三槽随机 | 启用随机池后固定 seed 重复运行 | 同一 seed 抽取结果一致；随机结果不改变状态到 slotId 的请求契约 |
| Boss 战斗技能优先级 | slot2 和 slot3 同时 Ready，存在合法战斗目标 | 优先请求 slot3；若技能系统因效果条件拒绝，可继续尝试 slot2；最多一个请求被接受 |
| 技能效果条件归属 | slot2 已有分身或 slot3 增益已生效 | 由 SkillSlotBinding.triggerPolicy 拒绝；Boss 不读取分身、增益或效果活动状态 |
| 战斗技能请求范围 | 分别在 Engage / Chase / Rage / SeekAlliance 运行 | 前三个意图按规则请求；SeekAlliance 不请求 slot1/2/3 |
| 3 秒未命中 | Boss 本体连续 3 秒未命中敌对玩家 | 请求一次 slot1；命中后计时清零；被护盾吸收的命中计入；分身、召唤物和塔命中不计入 |
| 3 秒未命中边界 | 没有合法敌对玩家目标 | 暂停计时，不请求 slot1；重新获得有效目标后从 0 开始 |
| Boss CD 独立 | 依次释放 slot1 / slot2 / slot3 | 三槽分别按 20 / 15 / 30 秒计时，释放一个不平移其他槽剩余 CD |
| Boss CD 起点 | 施放完成后检查进入冷却的时机 | CD 从 Commit 开始；Commit 前打断不启动本次 CD |
| Boss Disabled 暂停 | 某槽处于 Cooldown 时将其设为 Disabled，再恢复 | Disabled 期间剩余 CD 不变；恢复后从原剩余时间继续 |
| 地震波效果 | 40m 内放置非盟友目标并施放 slot1 | 移速/攻速降低 30%，持续 5 秒；盟友不计入 |
| 分身效果 | Boss 当前生命和攻击不同数值时施放 slot2 | 分身生命=施放时生命 20%，攻击=施放时攻击 50%，最长 8 秒，可被击杀 |
| 嗜血狂暴效果 | 施放 slot3 前后采样属性 | 移速与普攻攻速提高 50%，持续 8 秒，其他属性与技能 CD 不变 |
| 结盟主动申请冷却 | 连续申请局 | Boss 申请从有效提交时开始 60s 冷却；玩家间申请为 120s；接受/拒绝响应不触发自己的冷却 |

### 4.3 结盟系统

| 项目 | 测试方式 | 通过标准 |
| --- | --- | --- |
| 弱者+Boss 时长（15-20s） | 弱者爆发窗口扫描 | 强者有反制空间，弱者有“有且仅有一赌”窗口 |
| 玩家+玩家（30-45s） | 双人合作击杀局 | 够打死 Boss 但不足以轻松翻脸双赢 |
| 确认与翻脸 | 模拟 2-3s 确认/攻击对方 | 攻击立即破裂并触发结盟惩罚仇恨（计入总分） |
| 主动申请硬门槛 | Boss 仇恨非零 / 玩家生命 29% / 玩家生命 30% / Boss Rage / 单人残局 | Boss 仇恨不阻止申请或接受；生命 <30%、Rage 或非双人残局时申请者自行禁止；正好 30% 允许 |
| 3 秒申请等待期 | 申请后观察申请者、目标及其归属单位 | 申请者及召唤物、塔停止伤害目标；目标移动、攻击、技能和归属单位完全自由；其他数值不变 |
| 申请者主动攻击 | 等待期内申请者手动攻击目标 | 本次申请立即失效，归属单位恢复攻击，已开始的申请冷却不返还 |
| 目标主动攻击 | 等待期内目标用普攻或敌对主动技能攻击申请者 | 视为拒绝，立即解除申请者攻击限制 |
| 目标归属单位伤害阈值 | 目标召唤物、塔在等待期内累计造成 4.9% / 5% / 5.1% 最大生命实际伤害 | 4.9% 与 5% 不拒绝；严格超过 5% 视为拒绝 |
| Boss 主动提议等待期 | Boss 向玩家发起提议 | Boss 本体、召唤物和塔停止攻击目标玩家 3 秒；玩家保持自由；玩家主动攻击 Boss 即拒绝 |
| 申请冷却起点 | 主动申请后被接受 / 拒绝 / 超时 | 三类结果均从有效提交时开始冷却；Boss 60s，玩家间 120s；无效提交不进入冷却 |
| 响应不触发冷却 | 接受或拒绝他人申请；接受 Boss 主动提议 | 响应方自己的主动申请冷却保持不变 |
| 玩家间协商锁 | 玩家间申请被拒绝或超时 | 双方 5s 内不能再次互相申请 |
| Boss 结盟后封锁 | Boss + 玩家结盟期间，以及结束后的第 0-9 秒和第 10 秒 | 期间玩家间申请与接受均拒绝；到游戏时间满 10s 后解除 |
| 结盟时长高频调整 | 同一玩家同一游戏秒造成 100 次伤害/DoT 跳伤 | 只执行一次 -1/+1 秒，其余记录 rate_limited |
| 召唤物归属去重 | 玩家本体、分身、召唤物和塔同秒命中 Boss | 全部归到玩家 ownerId，只调整一次 |
| 时长调整边界 | 当前结盟仅剩 0.5 秒或已到基础时长 | 先应用 delta 再钳位；到 0 立即结束，延长不超过基础时长 |
| 结盟实时快照覆盖 | 在 10 秒快照周期中段开始/结束结盟 | allianceVersion 立即递增；目标过滤立即更新；其他战略字段不重掷 |
| 正常到期快照刷新 | 结盟时间自然归零 | T0 立即刷新目标/求生/结盟区块/AI 视角；T+3 增加 5000 追杀仇恨并立即刷新目标排序 |
| 死亡解除结盟 | 在玩家间或 Boss + 玩家结盟期间淘汰任一玩家 / 击杀 Boss | 涉及死亡方的结盟立即结束；不进入缓冲、不生成追杀仇恨；allianceVersion 立即递增 |
| 回魂契约 | 死亡且双方防具宝石状态矩阵 | AI 死亡自动申请；trust≥60 同意，trust<60 拒绝；任一方缺少防具宝石直接拒绝 |
| 强者反制 | 隐身/冰冻/位移技能局 | 强者不无解 |

### 4.4 心争夺

| 项目 | 测试方式 | 通过标准 |
| --- | --- | --- |
| 10s 拾取读条 | 站立/受击/移动三种状态 | 受击回退不归零，移动重置 |
| 打断抢夺 | 双人抢心局 | 打断与淘汰掉落正确，心可被双方争夺 |
| 交付过场 | Boss 死亡后交付局 | 阿蛮赶来收取，游戏结束，无卡死 |
| 尾刀化检测 | 统计击杀者与获胜者 | 最后一击者获胜比例不过高 |

### 4.5 塔与囤塔

| 项目 | 测试方式 | 通过标准 |
| --- | --- | --- |
| 战力构成 | 已放塔/未放塔对比局 | 囤塔不计战力，放塔后实时计入 |
| 结盟锁定 | 结盟期间尝试放塔 | 锁定生效，结束后解锁 |
| 囤塔翻盘 | 弱者囤塔局 | 结盟后风筝可用且有翻盘可能 |
| 配额与保底 | 长局资源扫描 | 每局 4 座上限、正常流程 2 座保底达成 |

### 4.6 死亡与稳定性

| 项目 | 测试方式 | 通过标准 |
| --- | --- | --- |
| 出局后 solo | 一方出局局 | 幸存者 solo 成功或失败，双方均失败时统计层记为双输 |
| 双输 | 双方死亡/都打不动局 | 系统分别将双方结算为失败，统计层记录为双输 |
| Boss 死亡掉落 | 固定 seed 击杀 Boss | 发布完整 BossDiedEvent 并调用 ILootDropService 请求恶魔之心掉落；Boss 不结算胜负 |
| AI 死亡刷新 | 两名 AI 固定不同快照相位，在相位点之外产生玩家/Boss 死亡 | AI 立即刷新全部活动快照并响应，不能等到各自下一个快照点 |
| AI 卡死 | 长时间运行 | 无 AI 原地发呆、寻路死循环 |
| 海平面死区 | 全水位状态扫描 | Boss、心、玩家不被卡进不可达区域 |
| AI 稳定性前置 | 单独跑 AI 质量测试 | 卡死/寻路失败率低于阈值，有效局率 ≥ 90% 后才进入数值扫描 |

### 4.7 跨系统一致性

| 项目 | 测试方式 | 通过标准 |
| --- | --- | --- |
| 加速一致性 | 同种子 1x vs 8x 各 N 局 | 胜负、时长、事件序列一致 |
| 回放保真度 | Replay 重现 vs 实跑 | 关键事件逐帧一致 |

## 六、调参循环与 MCP 操作流程

1. 读取 MCP 工具清单，确认场景加载、参数设置、运行控制、遥测读取、录屏控制等工具。
2. 加载测试场景，注入测试人格与固定种子。
3. 跑基线：默认参数 × 核心场景矩阵，先过运行有效性门禁（有效局率 ≥ 90%）。
4. 分析基线：若未达标，进入参数扫描（网格/二分）。
5. 修改参数 → 重跑同种子组 → 对比指标。
6. 命中异常 → 自动写 Replay + 录屏 + 进入复验队列。
7. 关键回归：1x 速度复验核心场景。
8. 生成报告：推荐数值表 + 异常汇总 + 综合总结。

> 每次修改必须记录：参数、原因、样本、结果差异，保证可审计。

---

## 七、回放与录制

### 7.1 状态回放（Replay）

- 记录：随机种子、输入序列、状态快照、事件时间线。
- 用途：逐帧重现、异常复现、加速一致性校验。
- 文件：`replay/<scenario>_<seed>.json`。

### 7.2 视频录制

- 常规批量跑不录视频；命中异常事件（双输、结盟成功、心被抢、AI 卡死、囤塔翻盘、Boss 提前苏醒）才自动录屏。
- 录屏局强制 1x-2x 速度，避免丢帧。
- 文件名：`video/<scenario>_<seed>_<event>.mp4`（以实际编码器输出为准）。
- 视频只用于人工复盘，不进入自动验收。

---

## 八、加速执行策略

| 层级 | timeScale | 用途 |
| --- | --- | --- |
| 批量扫描 | 4x-8x | 参数扫描、统计跑量 |
| 关键回归 | 1x | 核心场景最终验收 |
| 录屏采样 | 1x-2x | 异常局录制 |

- MCP 提供 `setTimeScale` 控制；必要时使用固定 `fixedDeltaTime` 保证物理稳定。
- 每个参数组先跑“加速一致性”校验：1x 与 8x 同种子结果一致才采用加速结果。

## 九、日志与异常分析

### 9.1 四层日志

1. 遥测日志：状态快照 JSON/CSV。
2. 事件日志：关键事件时间线。
3. Unity Console：异常、Warning、报错，通过 MCP 或 `Logs/` 读取。
4. Agent 运行日志：每次改参、跑局、判断记录。

### 9.2 异常检测

- 规则式：数值越界、NaN/Infinity、结盟成功率 0%/100%、双输率超限、时长突变、DPS/战力异常、AI 卡死、心长时间无人拾取。
- 统计式：与基线 z-score / IQR 离群、参数梯度跳变、同参数方差过大。
- 输出“异常卡片”：参数、场景、种子、复现路径、发生时间、影响指标、疑似根因、复现命令。

### 9.3 异常闭环

命中异常 → Replay + 录屏 + 复验队列 → 对比正常局 → 分类为“数值问题 / 机制问题 / 随机噪声” → 调参重测或标为已知问题。

## 十三、风险与边界

1. 浮点波动降低可测试性：必须保留固定种子与判定开关。
2. 加速可能改变物理/AI 决策：任何加速结果先过一致性校验。
3. 录屏拖慢测试：只对采样局与异常局开启。
4. AI 人格不能完全代表人类：最终数值需要人工抽检与少量真人测试。
5. 当前单机权威逻辑先测；联机状态同步落地后再补网络场景。

## 十四、AI 稳定性测试（阶段零，前置）

### 14.1 目标

- 在数值扫描前先确保 AI 行为稳定、可复现、无卡死。
- 通过本阶段验收后，AI 数据才可作为数值结论的依据。

### 14.2 测试用例

| 编号 | 用例 | 观察点 |
| --- | --- | --- |
| A-1 | 寻路与移动 | 任意出生点导航到目标点，无卡死、无绕路、无不可达 |
| A-2 | 行为状态机 | 每种人格遍历移动/攻击/风筝/治疗/拾取/逃跑/跟随/结盟/翻脸/拾心状态，无非法迁移 |
| A-3 | 战斗循环 | 攻击、技能、冷却、受击回退行为正确 |
| A-4 | 读条行为 | 开箱/采集/结盟确认/心拾取：受击回退、移动取消正确 |
| A-5 | 人格差异 | 合作/军备/背叛/逃跑/风筝人格在对应场景表现符合行为统计 |
| A-6 | 异常场景 | 卡墙角、海平面封路、心在不可达区域、Boss 自由移动、双方同时死亡、超时 |
| A-7 | 长时间稳定性 | 连续 20 局无死锁、无泄漏、无卡死 |
| A-8 | 回放一致性 | 同种子 Replay 重现与实跑一致 |

### 14.3 验收标准

- 有效局率 ≥ 90%
- 卡死 / 寻路失败率低于阈值（建议 ≤ 2%）
- 无状态机非法迁移
- 同种子可复现
- Unity Console 无新增 Error（已知警告可记录）

### 14.4 执行流程

1. 加载 AI 稳定性场景，注入全部测试人格与固定种子。
2. 逐用例运行（每用例 10-20 局/种子组）。
3. 收集有效性标记、事件日志与 Replay。
4. 对失败局定位：AI bug / 场景 bug / 数值 bug。
5. AI bug 直接修复或生成问题清单；修复后复验。
6. 有效局率达到标准后，生成《AI 稳定性报告》，才进入数值扫描阶段。

### 14.5 输出物

- `report/ai_stability/`：稳定性报告（有效局率、失败用例、修复记录）
- `replay/ai_stability/`：失败局回放
- `video/ai_stability/`：异常局录屏
