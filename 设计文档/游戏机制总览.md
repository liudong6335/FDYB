## 一、游戏概述

### 1.1 核心理念

《分道扬镳》是一款 1v1 策略竞技游戏（PvPvE），核心体验是"动态关系博弈"：两名玩家从被迫合作逐渐走向必然对立，在共享的恶魔（Boss）压力下进行资源争夺、心理博弈和策略抉择。

- 决策重于操作，攻击对手会加速共同威胁，形成经典囚徒困境。
- Boss 行为可预测，玩家需要动态判断"合作还是对抗"，并持续预判对手决策。
- 极端情况下，弱势一方可以阶段性帮助 Boss 压制另一方。

### 1.2 基本信息

| 项目 | 内容 |
| --- | --- |
| 玩法类型 | 1v1 策略竞技（PvPvE） |
| 单局时长 | 10-18 分钟（设计目标） |
| 美术风格 | 3D 卡通风格，2.5D 视角 |
| 开发引擎 | Unity 6.0 LTS |
| 运营平台 | PC（Steam） |

### 1.3 故事背景

故事发生在封禁之地。百年之前恶魔哈里斯被巫族大祭司囚禁于此，力量已日渐虚弱。两名外出历练的游侠先后误入此地，为了生存被迫并肩作战，又因资源匮乏而相互竞争。

一天，二人击败一只恶魔仆从后，巫族大祭司的孙女阿蛮从天而降。她冒险进入封禁之地，只为取得恶魔之心拯救生命垂危的大祭司，并承诺成功后带二人通过祭台传送离开。

祭台因年久破损，能量只够两人离开。三人约定阿蛮留下修复传送阵，二人去击杀恶魔，谁先取得恶魔之心并交给阿蛮，谁就能先离开。祭台激活 8 分钟后恶魔会苏醒；在苏醒前，二人需找到镇压恶魔的两件圣物（日之石与月之石），并用巫族装备制作秘法合成能杀死恶魔的装备。

### 1.4 胜负条件

| 条件 | 结果 |
| --- | --- |
| 击杀恶魔（Boss）取得恶魔之心，并交给阿蛮 | 交付方获胜 |
| 玩家自身死亡 | 死亡者失败 |
| 对手成功将恶魔之心交付给阿蛮 | 交付方获胜，另一方失败 |
| NPC 阿蛮在护送途中死亡 | 双方失败 |
| 双方都死亡 | 双方失败 |

> ⚠️ 当前代码只落地了阶段状态机（Victory / GameOver）与阿蛮死亡触发 GameOver；Boss、恶魔之心、交付判定均未实现。

## 二、核心循环与阶段流程

### 2.1 阶段总览（初版设计）

| 阶段 | 时间 | 内容 |
| --- | --- | --- |
| 第一阶段：护送 | 0-4 分钟 | 护送阿蛮前往安全屋，保护她不被恶魔仆从击杀 |
| 第二阶段：自由探索与争夺 | 4-10 分钟 | 寻找宝箱、获取物品与金币，强化属性，应对对手和恶魔威胁 |
| 第三阶段：恶魔之心争夺 | 7-18 分钟 | 恶魔苏醒后击杀 Boss 夺取恶魔之心，结盟或背叛，交付阿蛮获胜 |

> ⚠️ 阶段时间线是初版数值假设。当前实现中，护送阶段结束由"任务区域链全部完成"驱动，没有 4 分钟硬性截止；Boss 苏醒计时、结盟、掷色子等规则尚未实现。

### 2.2 当前阶段状态机（✅ 已实现）

`EscortPhaseController` 维护 `GamePhase`：

```
Menu → Escort → Exploration → BossBattle → Victory / GameOver
```

- `Escort`：护送阶段，区域链推进中，玩家离开阿蛮过远会持续掉血。
- `Exploration`：区域链全部完成后进入；当前仅切换状态，探索玩法仍由场景中的宝箱/商店/怪物承担。
- `BossBattle / Victory`：仅存在于枚举与 HUD 文案，尚无实际 Boss 战与胜负结算逻辑。
- `GameOver`：阿蛮死亡时触发。

### 2.3 当前完整玩法循环（✅ 已实现部分）

```
护送阿蛮进入任务区域
  → 区域内任务物品提前可见（随机刷出点）
  → 阿蛮走向物品并采集（2.5s，受击回退）
  → 采集完成 → 区域完成 → 区域附近刷新宝箱
  → 玩家开箱/击杀怪物获取装备与金币
  → 阿蛮前往下一区域（途中可触发救援）
  → 全部区域完成 → 进入探索/Boss 阶段（待实现）
```

## 四、护送与任务区域系统

### 4.1 区域链（✅ 已实现）

- `QuestManager` 管理区域链：区域A → 区域B → 区域C → ... → Boss 区域，顺序固定，NPC 不回头。
- 每个 `QuestArea` 配置：区域 ID、半径、任务物品随机刷出点、怪物等级/数量、入口点、宝箱掉落配置。
- 怪物按区域激活，区域完成后停止复活；全部完成后触发 `OnAllAreasComplete`。

### 4.2 任务物品生命周期（✅ 已实现，按《任务物品生命周期设计》方案 A）

```
区域激活 → 任务物品在随机刷出点提前生成（发光可见）
  → 阿蛮走向物品位置
  → 到达后开始采集（2.5s，每次受击回退 0.5s）
  → 采集完成 → 物品销毁
  → 区域完成 → 宝箱在区域附近刷新
  → 下一区域物品立即生成
```

> 实现细节：宝箱刷新中心为区域中心 + 配置半径（`ChestDropConfig.spawnRadius`），初版设想是"阿蛮当前位置 2-3 米"，二者需要按场景表现取舍。

### 4.3 阿蛮移动状态机（✅ 已实现）

`NavigateToArea → Searching → ReadyToCollect → InTransit → AllComplete`

- 区域间移动支持救援：玩家血量低于 15% 且距离 25 米内时，阿蛮回头走向两区域中点接应；每段转移只触发一次。
- 附带怪物回避、卡死检测、随机速度变化、NavMesh + CharacterController 同步。

### 4.4 玩家距离惩罚（⚠️ 已调整）

| 初版设计 | 当前实现 |
| --- | --- |
| 与阿蛮距离超过 20 米：移速减半、攻击减半、生命流失 | 距离超过 30 米：持续流失生命，`10 + 超出距离 × 2 HP/s` |

### 4.5 护送奖励（⚠️ 已调整）

| 初版设计 | 当前实现 |
| --- | --- |
| 护送结束后按玩家对幽灵伤害结算，伤害高者得精品装备 | 每完成一个任务区域，在区域附近刷新宝箱；最终护送奖励按区域宝箱配置发放 |


## 六、掉落、背包与商城

### 6.1 全局掉落预算（✅ 已实现）

- `LootBudgetManager` 控制全图产出总量：装备类按 `maxCount` 限量，药水/金币等 `unlimited` 不限量。
- 所有宝箱/怪物掉落统一走 `PickOne(dropEntries)`：过滤预算 → 按权重抽取 → 扣减 → 返回 `GameItem`。
- 每局开始（护送启动）调用 `Reset()`。

### 6.2 掉落物生命周期（✅ 已实现）

| 来源 | 行为 |
| --- | --- |
| 宝箱 | 开箱动画后，掉落物从箱口飞向玩家（抛物线，约 0.6s） |
| 怪物 | 先落地弹跳，尸体消失（约 1s）后飞向击杀者 |
| 玩家死亡掉落 | 停在地面，玩家靠近 4 米自动拾取，其他玩家也可拾取 |
| 背包已满 | 掉落物落回地面，腾出空间后可再次拾取 |

- 怪物掉落归属：击杀者优先，无击杀者回退最近玩家。
- 死亡掉落规则：按物品配置 `dropOnDeath + deathDropChance`，不走全局预算。

### 6.3 背包与装备（✅ 已实现）

| 规则 | 内容 |
| --- | --- |
| 背包容量 | 20 格，每格一件，金币不占格 |
| 装备部位 | 5 个：护腕 / 铠甲 / 护肩 / 裤子 / 武器宝石 |
| 自动穿戴 | 首次获得该部位装备自动穿戴；同类更强装备可手动/自动替换 |
| 自动合成 | 同部位、同类型、同稀有度的两件装备自动合成下一稀有度（普通 → 精品 → 稀有 → 史诗） |
| 属性加成 | 生命词条加固定 HP；DPS 词条按 `statValue / 100` 的百分比倍率叠加 |
| 出售价 | 按稀有度：普通 25 / 精品 50 / 稀有 100 / 史诗 200 / 神话 500 |

> ⚠️ 初版设计是"两个同名普通装备自动合成精品"，当前实现扩展为同基装备逐级合成；初版将 DPS 视为固定数值，当前实现为百分比倍率。

## 十三、现有机制整体评价（优势 / 劣势）

### 13.1 优势：值得保留的设计

| # | 优势 | 说明 |
| --- | --- | --- |
| 1 | 合作-竞争双目标结构 | 护送是共享目标，宝箱/商店/出售池是竞争资源，天然形成囚徒困境，博弈空间充足 |
| 2 | 收益与护送行为绑定 | 宝箱由区域完成事件驱动，玩家必须参与护送，解决了"离开 NPC 跑图捡箱更赚"的问题 |
| 3 | 决策重于操作 | 点击移动、自动导航、读条规则都简单直接，上手门槛低，符合策略竞技定位 |
| 4 | 怪物复活升级压力曲线 | 击杀幽灵会升级复活，逼玩家在"清怪保阿蛮"和"攒资源成长"之间权衡 |
| 5 | 全局掉落预算 | 装备产出总量可控、归属清晰（击杀者优先），单局数值不膨胀 |
| 6 | 数据层契约先行 | 背包/出售/合成 API 原子性 + 事件驱动，UI 与数据解耦，工程上稳健 |
| 7 | 玩家 AI 与角色卡 | 可用于自动测试、人机模式和平衡验证，是低成本迭代资产 |
| 8 | 设计文档体系完整 | 亲和度双路线、陷阱互坑、Steam 房间都有完整设计稿，后续方向明确 |

### 13.2 劣势与风险：需要解决

| # | 劣势 / 风险 | 具体影响 |
| --- | --- | --- |
| 1 | 核心闭环缺失 | Boss、恶魔之心、胜负结算未实现，一局游戏无法完成，是所有问题的根 |
| 2 | 玩家间对抗缺位 | 无 PvP 伤害规则、无抢箱/打断/陷阱/引怪手段，对手在当前玩法里存在感弱，"动态关系博弈"停留在文档 |
| 3 | 阶段压力单调 | 区域链 + 固定复活怪形成重复循环，缺少全局时间压力（如恶魔苏醒倒计时）和随机事件 |
| 4 | 经济未闭环 | 金币产出与消耗没有平衡设计，商店硬编码，出售池/限购/刷新规则未接 UI |
| 5 | 装备深度不足 | 只有 HP、DPS 两类词条，无套装、无主动效果、无特色机制，养成反馈单一 |
| 6 | 怪物类型单一 | 目前只有恶魔仆从一种（靠等级区分），没有精英/Boss/自然型-智慧型差异，战术深度有限 |
| 7 | 信息反馈不完整 | 无小地图情报、伤害数字、对手意图提示，玩家难以读取对方路线，博弈反馈弱 |
| 8 | 惩罚偏被动 | 远离阿蛮 30 米直接持续掉血，缺少"选择、反应、反制"的过程，容易变成纯扣分惩罚 |
| 9 | 开箱博弈浅 | 先到先得 + 读条 + 受击回退，缺少对手主动干扰（打断道具、陷阱、争夺） |
| 10 | 数值未调优 | 怪物伤害、装备倍率、掉落权重、合成数值均未经测试，DPS 词条改成百分比倍率后手感需要验证 |
| 11 | 工程债 | 旧 Input API 未迁移、商店/UI 硬编码、多处占位面板、无主菜单与场景管理 |
| 12 | 配置不数据化 | 大量数值散落在代码字段和 Inspector，缺统一配置表和运行时调参工具，平衡迭代慢 |
| 13 | 叙事与玩法脱节 | 8 分钟苏醒、圣物、祭坛、恶魔之心等故事设定尚未进入玩法，世界观没有形成玩法压力 |

### 13.3 结论与调整方向

1. **先把"一局游戏"做完整**：补 Boss 与恶魔之心、胜负结算，并把"恶魔苏醒倒计时"作为全局压力线，让护送/探索/争夺都有时间锚点。
2. **再补"对手感"**：落地玩家间对抗（PvP 规则、抢箱/打断、引怪、出售池博弈），这是当前机制设计上最缺的一层。
3. **后做机制扩展**：亲和度双路线、陷阱互坑按设计稿分批接入，但不应作为第一阶段依赖。
4. **同步清工程债**：统一数值配置、补齐 HUD 信息、迁移 Input System、建立正式主场景，避免机制越加越难改。
