# 道具系统设计

## 一、概述

游戏中的道具产出与流转，涵盖宝箱掉落、怪物掉落、淘汰掉落、商城购买四种来源。

**核心机制**：全局掉落预算（总量恒定，个体依赖概率） + 每次掉落只产生一件物品。

**背包与操作**：
- 背包容量有限，满时无法拾取新物品
- 物品出售后出现在商城，其他玩家可购买
- 物品销毁：直接移除，不给金币，永久消失
- 三种玩家操作：使用（消耗品）/ 出售 / 销毁

---

## 二、核心概念

### 2.1 GameItemDefinition（ScriptableObject）

所有道具的蓝图资产，一次定义全局复用。

```
public class GameItemDefinition : ScriptableObject
{
    // 基础
    public string itemId;
    public string itemName;
    public ItemType itemType;         // Equipment / Consumable / Currency
    public ItemRarity rarity;

    // 装备属性
    public EquipmentSlotType slotType;
    public StatType statType;
    public float statValue;

    // 消耗品
    public float healAmount;

    // 货币
    public int goldAmount;

    // --- 新增字段 ---
    public Sprite icon;               // UI 图标（背包 / 商城用）
    public GameObject dropPrefab;     // 3D 模型（null = 纯 UI 道具）
    public bool dropOnElimination;          // 永久淘汰时是否可掉落
    public float eliminationDropChance;     // 淘汰掉落概率（0~1，默认 0 = 不掉）
    public int shopPrice;             // 商城售价（0 = 不出售）
    [TextArea] public string tooltip; // 鼠标悬浮提示

    public GameItem ToGameItem();     // 运行时转成 GameItem
}
```

### 2.2 DroppedItem（MonoBehaviour）

场景中的 3D 掉落物组件，挂在 dropPrefab 上，管理从生成到进入背包的完整生命周期。

| 模式 | 来源 | 行为 |
|------|------|------|
| 直接飞行（delay=0） | 宝箱 | 从宝箱口飞出，抛物线 → 进背包 |
| 落地→飞行（delay>0） | 怪物 | 先掉地弹跳，等尸体消失后飞向击杀者 |
| 纯地面（无飞行目标） | 淘汰掉落 | 停在地面，玩家靠近自动拾取 |

- 掉落物保持预制体原始大小，代码不做强制缩放
- pickupRange（默认 4 米）暴露在 Inspector，可调

```
public class DroppedItem : MonoBehaviour
{
    private GameItem itemData;
    private PlayerMove flyTarget;
    private float groundDelay;    // 地面停留时间
    private float flyDuration;    // 飞行持续时间（固定 0.6s）
    private enum Phase { Ground, Flying, Done }

    // 统一入口
    public void Launch(GameItem item, PlayerMove target, float groundDelay = 0f);

    // 外部触发：从地面切换到飞行（怪物尸体消失后调用）
    public void BeginFlight(PlayerMove target);

    void Update()
    {
        Ground 阶段：原地弹跳 + 自动拾取检测（靠近 pickupRange 自动进背包）
        Flying 阶段：抛物线 + 旋转（保持预制体大小）
        到达后 → 检查背包容量
            ├─ 有空间 → 进背包，销毁自身
            └─ 已满 → 停止飞行，落回地面，等待玩家腾出空间
    }
}
```

### 2.3 LootBudgetManager（全局单例）

掉落总量的控制核心，所有掉落来源统一经过此处查询和扣减。

| 方法 | 说明 |
|------|------|
| `InitFromConfig(BudgetEntry[])` | 初始化预算表 |
| `CanDrop(string itemId)` | 剩余是否 > 0 |
| `PickOne(List<DropEntry>)` | **核心方法**：过滤 + 加权抽选 + 扣减，返回 GameItem / null |
| `Reset()` | 重置所有预算（每局开始调用） |

**PickOne 流程**：

```
输入：有概率掉落的所有条目（含 weight）
  |
  ▼
① 过滤：只保留 budget.CanDrop(itemId) == true 的条目
  |
  ▼
② 如果过滤后为空 → 返回 null（这件不掉）
  |
  ▼
③ 加权抽选：按 weight 比例 roll 一件
  |
  ▼
④ budget.Consume(itemId) → 剩余量 -1
  |
  ▼
⑤ 返回对应的 GameItem
```

例如配置为 A 可出 5 件、B 可出 10 件、C 可出 8 件：

```
第一次开箱：A(5) / B(10) / C(8) 都可选，按权重 roll → 出了 B → 预算剩 A(5) B(9) C(8)
...
多次之后：A 出完 → A(0) B(3) C(2)，roll 时自动跳过 A，只从 B 和 C 里按比例抽
全部出完：A(0) B(0) C(0) → PickOne 返回 null，不再掉落
```

**无限预算**：BudgetEntry.unlimited = true 的物品不受总量限制（药水、金币），remaining 恒为 int.MaxValue，TryConsume 不扣减。装备等 limited 物品按 maxCount 限量。

**重置时机**：EscortPhaseController 开始游戏时调用 `Reset()`，确保每局产出可控。

### 2.4 Backpack & Inventory（背包系统）

玩家背包由 InventoryManager 管理，每个玩家独立。

**背包容量**：
- 固定格数（如 20 格），每格存放一件物品
- 装备栏独立于背包，不计入背包容量
- `PlayerInventory` 新增属性：
```
public class PlayerInventory
{
    public Dictionary<EquipmentSlotType, GameItem> Equipped = ...;
    public List<GameItem> Backpack = ...;
    public int Gold;

    // 新增
    public int maxSlots = 20;
    public bool IsFull { get { return Backpack.Count >= maxSlots; } }
}
```

**容量校验时机**：

| 场景 | 行为 |
|------|------|
| DroppedItem 到达玩家 | 检查背包，有空间才进背包；已满则落回地面 |
| 商城购买 | 检查背包，已满则提示无法购买 |
| 宝箱直接加物品 | 检查背包，已满则提示先腾空间 |

**已在地上但背包已满的 DroppedItem**：
- 保持在地面，变成地面拾取模式（同怪物掉落物的地面阶段）
- 玩家靠近时显示背包已满提示
- 玩家腾出空间后，再次靠近点击可拾取

## 三、四种掉落来源

### 3.1 宝箱掉落

**触发时机**：宝箱打开，开箱动画结束后

**配置方式**：宝箱预制体上挂 TreasureChest 组件，配置 `DropEntry[]`

```
[System.Serializable]
public class DropEntry
{
    public GameItemDefinition itemDef;  // 掉什么
    public float weight = 1f;           // 相对权重
}
```

**执行流程**：

```
宝箱 open 动画播放结束（WaitForOpenAnimation）
  → budget.PickOne(chestDropEntries)
    ├─ 返回 GameItem → 优先 itemDef.dropPrefab，没有则用 defaultDropPrefab
    │                   → DroppedItem.Launch(item, player, delay=0)
    │                   → 飞出宝箱口 → 抛物线 → 进背包
    └─ 返回 null → 兜底 fallbackGold（宝箱必出物品）
  → 金币有 3D 模型时走 DroppedItem；无模型时才用旧金币视觉特效
```

**必出物品**：宝箱掉落表里包含无限预算的药水/金币时，预算耗尽后仍能出药水/金币；掉落表异常时兜底金币。

### 3.2 怪物掉落

**触发时机**：怪物死亡时

**配置方式**：MonsterDrop 组件挂在 DemonMinion 预制体上

```
public class MonsterDrop : MonoBehaviour
{
    [SerializeField] private List<DropEntry> dropEntries;

    public void OnDeath()  // 在 DemonMinion.OnHealthDepleted 中触发
    {
        // 击杀者优先，无击杀者时回退最近玩家
        PlayerMove target = ResolveTarget(killerTransform);
        if (target == null) return;
        GameItem item = LootBudgetManager.Instance.PickOne(dropEntries);
        if (item == null) return;
        var go = Instantiate(item.definition.dropPrefab, 尸体位置, 随机旋转);
        var dropped = go.GetComponent<DroppedItem>();
        dropped.Launch(item, target, float.MaxValue); // 先停地面
        // 等尸体隐藏事件（DemonMinionLifecycle.OnBodyHidden）后再飞
        lifecycle.OnBodyHidden += () => dropped.BeginFlight(target);
    }
}
```

**视觉行为**：从尸体位置弹出 → 掉地上弹跳 → 等尸体隐藏（约 1s）→ 飞向击杀者 → 进背包

### 3.3 淘汰掉落

**触发时机**：玩家永久淘汰时（回魂申请期间不掉落，回魂成功后不掉落）

**执行逻辑**（玩家淘汰回调中新增）：

```
玩家永久淘汰
  → DropItemsOnElimination()
  → 获取背包，倒序遍历（避免 RemoveAt 索引错乱）
    → 筛选 item.definition?.dropOnElimination == true
    → 概率判断：Random.value < item.definition.eliminationDropChance
    → 命中：从背包移除
    → Instantiate(dropPrefab, 淘汰位置)
    → DroppedItem.Launch(item, null, float.MaxValue)  // 纯地面模式
    → 玩家靠近 4 米（pickupRange）自动拾取
```

**掉落概率**：GameItemDefinition.eliminationDropChance（0~1），默认 0 = 不掉；需要某物品在永久淘汰时必掉时填 1。

**重要**：淘汰掉落不走 LootBudgetManager，从已有背包中丢出，不受总量限制。

### 3.4 商城购买

**触发时机**：玩家在 NPC 处打开商城，点击购买

**配置方式**：ShopConfig（ScriptableObject）

```
[CreateAssetMenu(menuName = "Game/Shop Config")]
public class ShopConfig : ScriptableObject
{
    public List<ShopEntry> itemsForSale;
}

[System.Serializable]
public class ShopEntry
{
    public GameItemDefinition itemDef;
    public int priceOverride;  // 覆盖 GameItemDefinition.shopPrice
    public int stockCount = -1; // -1 = 无限
}
```

**执行流程**：

```
玩家点击购买
  → 检查金币是否足够
  → InventoryManager.SpendGold(price)
  → InventoryManager.AddItem(itemDef.ToGameItem(), player)  // 直接进背包
```

**注意**：商城购买不经过 3D 掉落物，不经过预算系统。纯 UI 操作，直接进背包。

### 3.5 玩家出售（商城出现）

**触发时机**：玩家在背包中选择出售物品

**执行流程**：

```
玩家点击出售（通过 BackpackController UI）
  物品从背包移除
  玩家获得金币（按稀有度定价）
  物品进入 InventoryManager.SoldItems 共享池
  其他玩家打开商城时可见该物品
```

**数据存储**：InventoryManager 新增共享池

```
public class InventoryManager : MonoBehaviour
{
    public List<PlayerSoldItem> soldItems = new List<PlayerSoldItem>();
}
```

**商城 UI 变化**：ShopController 增加两个选项卡

- NPC商品选项卡：原有逻辑不变
- 玩家出售选项卡：来自 soldItems 池，其他玩家可见并购买，售出后从池中移除

**重要规则**：
- 出售者自己的商城界面看不到自己卖的物品
- 购买者支付金币给系统（出售者在出售时已获得金币）
- 可选：加入时间过期机制（如一定时间无人购买则下架）

### 3.6 物品销毁

**触发时机**：玩家在背包中选择销毁物品

**执行流程**：

```
玩家点击销毁（通过 BackpackController UI）
  弹出确认框（防止误操作）
  确认后物品从背包移除
  不给金币
  物品永久消失
```

**与出售的区别**：

| 操作 | 金币 | 物品去向 |
|------|------|---------|
| 出售 | 获得金币 | 进入商城共享池，其他玩家可买 |
| 销毁 | 不给金币 | 永久消失 |

## 五、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 每次掉几件 | 1 件 | 简化随机逻辑，每次开箱/击杀只有一个掉落物飞向玩家，视觉清晰 |
| 预算不足时的行为 | 跳过该物品 | 预算用完后自动不参与 roll，不影响其他仍有预算的物品 |
| count 不够需求 | 有多少给多少 | 预算剩余 1 件就掉 1 件，不强制匹配 minCount |
| 重置时机 | 每局开始 | LootBudgetManager.Reset() 在 EscortPhaseController 启动时调用 |
| 淘汰掉落走预算吗 | 不走 | 淘汰掉落从已有背包中丢出，不算新增产出 |
| 商城掉落走预算吗 | 不走 | 商城购买是玩家用金币交换，不受场景产出总量限制 |
| 物品无 dropPrefab | 直接加背包 | 纯 UI 道具（任务道具等）不生成 3D 模型，不走 DroppedItem |
| 背包满载时掉落物行为 | 落回地面，等待腾出空间 | 玩家可以有意识选择丢弃哪些物品腾空间 |
| 出售后物品去向 | 进入商城共享池 | 让两个玩家之间有间接的物品流通方式，不需要专门的交易系统 |
| 出售者能否看到自己的商品 | 不能 | 防止自己买回刷金币 |
| 销毁是否需要确认 | 需要 | 销毁不可逆，确认框防止误操作 |
| 商城如何展示玩家出售物品 | 增加一个选项卡 | 与 NPC 商品分开，清晰区分来源 |
| 宝箱必出物品 | 掉落表异常/预算耗尽时兜底金币 | 宝箱永远有掉落反馈 |
| 药水/金币总量 | 不受预算限制（unlimited） | 基础资源不设上限，装备类才限量 |
| 淘汰掉落概率 | eliminationDropChance 默认 0 | 默认不掉，按物品配置调整 |
| 淘汰掉落拾取 | 停地面，靠近 4 米自动拾取 | 其他玩家可捡，无需点击 |
| 怪物掉落归属 | 击杀者优先 | 谁打的归谁，击杀者无效回退最近玩家 |
| 怪物掉落时机 | 尸体消失后再飞 | 先让玩家看到掉落，再自动飞 |
| 掉落物大小 | 保持预制体原始大小 | 不做强制缩放 |

## 六、制作步骤

### 第一步：数据层

扩 GameItemDefinition，加字段（icon / dropPrefab / dropOnElimination / shopPrice / tooltip），用 ScriptableObject 定义第一批物品资产（药水、装备、宝石等）。

### 第二步：预算系统

新建 LootBudgetManager 单例，实现 PickOne() 核心方法，在 EscortPhaseController 启动时初始化。

### 第三步：视觉核心

新建 DroppedItem.cs，做 dropPrefab 预制体（可先用 placeholder 发光球），实现飞行/弹跳/拾取逻辑。

### 第四步：宝箱掉落

改 ChestDropConfig 为 DropEntry[]（itemDef + weight），改 TreasureChest.OpeningSequence() 走 budget.PickOne。

### 第五步：怪物掉落

新建 MonsterDrop 组件，挂在 DemonMinion 上，配置掉落表，在死亡时触发。

### 第六步：淘汰掉落

在玩家永久淘汰回调中调用 DropItemsOnElimination()，遍历背包丢出 dropOnElimination 物品。

### 第七步：背包 UI 增强（先做）

- BackpackController 增加容量显示（如 "背包 12/20"）
- 每件物品操作按钮：使用（消耗品）/ 出售 / 销毁
- 销毁弹确认框；出售进入 soldItems 池（与商城联动）

### 第八步：背包容量

在 PlayerInventory 中增加 maxSlots 和 IsFull，InventoryManager 添加/购买时检查，DroppedItem 用 IsFull 替换硬编码 20。

### 第九步：商城重构（最后做，等资源）

建 ShopConfig ScriptableObject，改 ShopController 数据源从硬编码改为引用 GameItemDefinition；增加 NPC商品 / 玩家出售 选项卡，后者读取 InventoryManager.soldItems 池。依赖 UI 图标资源，暂缓。

## 七、补充说明

1. **预算配置示例**：如果希望全图总共出 5 瓶大药水、10 个普通护腕、8 个稀有护肩，在 LootBudgetManager 的配置表中对应设置即可
2. **debug 可视化**：可以考虑在 LootBudgetManager 上加上 Debug 绘制功能，运行时查看每件物品的剩余预算
3. **空宝箱/空怪物**：宝箱预算用完或掉落表异常时兜底金币，保证必出；怪物预算用完则不掉落
4. **淘汰掉落归属**：淘汰掉落的物品其他玩家可以捡，增加交互策略深度

5. **宝箱怪物掉落**：部分宝箱可能生成怪物而非直接掉落道具。此类怪物已携带宝箱道具，死亡时会掉落**多件物品**（宝箱内的 N 件 + 怪物自身掉落 1 件）。

   - 宝箱道具路径：怪物死亡 → 直接掉落 N 件（不走预算，取自宝箱配置的 loot table）
   - 怪物自身路径：怪物死亡 → budget.PickOne() → 掉 1 件（走预算，取自 MonsterDrop 配置）
   - 怪物已开了的宝箱玩家不可再开
   - 具体实现（怪物 AI、寻路、开箱动画）归属怪物系统，道具系统只定义掉落规则和优先级
