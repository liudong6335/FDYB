# NPC 任务区域系统设计（修订版 v2）

---

## 一、当前系统的问题

- NPC 行走无意义：预设路径 + 随机偏离，走过去什么都没有然后折返，视觉上很蠢
- 玩家收益与 NPC 脱钩：宝箱按时间刷新，玩家离开 NPC 跑远捡箱子比护送收益更高
- 重玩体验固定：路径固定、权重固定，每次玩完全一样

---

## 二、核心设计思路

大方向确定，细节不确定。

- 大方向：NPC 依次推进各个任务区域，不往回走
- 细节：区域内任务物品随机分布，每次位置不同
- 驱动力：NPC 完成任务 = 刷新宝箱，玩家收益与护送行为绑定（正向激励）

---

## 三、区域与任务物品

### 区域定义
- 每个区域是一个半径范围，场景中放置区域配置数据
- 区域序列：区域A → 区域B → 区域C → ... → Boss 区域
- 区域之间的顺序固定，NPC 始终向前推进

### 任务物品
- 每个区域内预设多个随机刷出点
- NPC 进入区域后随机选一个点生成任务物品
- 单区域一次只刷一件
- 下次重玩时重新随机位置

---

## 四、NPC 完整行为状态机

```
                 区域A完成
                    │
                    ↓
┌─────────────────────────────────────────────────────┐
│               区域间移动（关键护送段）                │
│                                                     │
│  正常情况：NPC 直线导航至区域B                        │
│  救援情况：NPC 可朝区域A方向回头，最多到两区域中间    │
│  不允许：重新踏入区域A范围                            │
│  救援完成：NPC 重新导航至区域B                        │
└─────────────────────────────────────────────────────┘
                    │
              进入区域B
                    ↓
┌─────────────────────────────────────────────────────┐
│                   搜索阶段                           │
│  NPC 朝随机刷出点移动                                │
│  区域内怪物激活                                      │
└─────────────────────────────────────────────────────┘
                    │
              到达刷出点
                    ↓
┌─────────────────────────────────────────────────────┐
│                   采集阶段                           │
│  读条 2.5 秒                                        │
│  每次受击回退 0.5 秒                                │
│  漏 1-2 只怪不再卡死                                │
└─────────────────────────────────────────────────────┘
                    │
              采集完成
                    ↓
┌─────────────────────────────────────────────────────┐
│                   完成阶段                           │
│  箱子在 NPC 当前位置附近刷新                         │
│  下一区域任务物品生成                                │
│  NPC 开始导航至下一区域                              │
└─────────────────────────────────────────────────────┘
```

### 区域间移动的救援机制详解

这是新增的关键行为：

```
[区域A (已完成)] ──── [中间地带] ──── [区域B (目标)]
                        ↑ NPC 在此范围内
                          可回头救援
```

**触发条件：**
- NPC 正在从区域A 前往区域B 的途中
- 队友（P1/P2）血量低于救援阈值（例如 15%）
- 或队友被困在靠近区域A 的位置，被怪物围攻

**行为：**
- NPC 朝区域A 方向移动（不超过两区域中间点）
- NPC 不会重新踏入区域A 范围
- 队友脱离危险后，NPC 恢复导航至区域B
- 每个区域间转移段只触发一次救援

**边界限制：**
- 救援范围 = 区域A 半径边缘 到 两区域中间点
- 超过中间点 → NPC 自动掉头
- 区域A 范围内 → NPC 不进入（已完成，不做回头）

## 五、采集机制

### 基础参数
- 基础采集时间：2.5 秒
- 每次受击回退：0.5 秒
- 不设超时保护——数学上可自愈

### 受击回退模型

| 场景 | 实际耗时 | 说明 |
|------|---------|------|
| 区域怪全清 | 2.5 秒 | 最快速度 |
| 漏 1 只怪 | ~3.3 秒 | 单怪攻击间隔约 2 秒，净推进 1.5 秒/次 |
| 漏 2 只怪 | ~5 秒 | 玩家顺手清掉体验更好 |
| 3 只以上 | 更长 → 优先清怪 | NPC 本身也危险了 |

**结论：漏 1-2 只怪不会卡死进度，不需要超时保护。**

## 六、怪物节奏

```
NPC 进入区域
  ├→ 区域内怪物激活（按区域配置的等级/数量）
  │    ├→ 玩家清怪
  │    └→ NPC 采集
  └→ 采集完成
       ├→ 本区域怪物逐步停止生成
       ├→ 箱子刷新
       └→ NPC 走向下一区域 → 区域间移动
            ├→ 正常：直接导航过去
            └→ 队友危险 → 触发救援（回头至中间点）
                 └→ 安全后继续导航
```

---

## 七、宝箱与收益

- 宝箱只在 NPC 采集完成时刷新
- 刷新位置：NPC 当前位置附近半径 2-3 米
- 不存在任何其他宝箱刷新途径
- NPC 完成后立即走向下一区域

---

## 八、玩家体验预期

### 完整玩法循环

```
保护 NPC 进入区域
  → 一起找任务物品
  → NPC 站定采集（2.5s）
    → 有怪攻击 → 读条被回退 → 玩家补刀
    → 采集完成 → 箱子刷在 NPC 身边 → 开箱
  → 保护 NPC 去下一区域（区域间移动）
    → 队友落后/危险 → NPC 回头到中间点接应
    → 安全后继续前进
  → 进入下一区域 → 重复
```

### 驱动力变化

当前：扣血惩罚 → 被动回来（不爽）
改为：箱子在 NPC 身边刷新 → 主动回来（爽）

## 九、需新增/改造的组件

| 组件 | 类型 | 说明 |
|------|------|------|
| QuestManager | 新增 | 管理区域链、当前区域、完成状态、解锁下一区域 |
| 区域配置数据 | 新增 | 每个区域的位置/半径/刷出点列表/关联怪物等级 |
| NPC 状态机 | 改造 NPCGoddessMovement | 替换旧 Deviation/路径行走逻辑 |
| 采集进度系统 | 新增采集组件 | 管理读条、受伤回退、触发完成事件 |
| 区域间救援逻辑 | 新增行为 | NPC 在转移段回头至中间点的条件与限制 |
| 宝箱触发 | 改造 GameManager | 去掉定时刷箱子，由采集完成事件触发 |
| 怪物激活 | 改造 GameManager | 改为按区域激活/停用怪物 |
