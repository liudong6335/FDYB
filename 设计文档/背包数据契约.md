# 背包数据契约（InventoryManager API）

> 状态：已定稿（2026-08-13）
> 目的：在 UI 原型和数据层实现前，先固定数据结构与公开 API，避免 UI 与数据层互相返工。

## 一、设计原则

1. UI 和玩法系统只通过 `InventoryManager` 的公开 API 操作数据，不直接增删 `Backpack` / `Equipped`。
2. 所有写入接口要么成功完成整个操作，要么失败且不产生任何状态变化（原子性）。
3. 容量、金币、归属、上架等边界规则统一由数据层判定，UI 只负责展示与交互。
4. 数据层不持有 UI 引用，不负责弹窗；销毁二次确认属于 UI 职责。
5. 成功写入后触发一次 `OnInventoryChanged`；失败不触发。
6. 玩家死亡即本局结束，背包数据层不需要处理复活。

## 二、数据模型

### 2.1 GameItem（运行时物品）

在现有字段基础上增加：

```csharp
public class GameItem
{
    // 现有字段：itemType / itemId / itemName / description / rarity / slotType / statType / statValue / healAmount / goldAmount / definition
    public string instanceId;   // 唯一实例 ID，ToGameItem() 和 Clone() 时生成
}
```

规则：

- `itemId` 是物品种类 ID，多个实例可相同；`instanceId` 是运行时实例 ID，必须唯一。
- 所有按物品操作（使用、出售、销毁、购买、下架）必须传入背包或出售池内的原始实例，数据层用实例身份校验。
- 当前设计每格一件，不做堆叠。

### 2.2 PlayerInventory

```csharp
public class PlayerInventory
{
    public Dictionary<EquipmentSlotType, GameItem> Equipped;
    public List<GameItem> Backpack;
    public int Gold;

    public int maxSlots = 20;
    public int UsedSlots => Backpack.Count;
    public bool IsFull => Backpack.Count >= maxSlots;
}
```

规则：

- 背包每格一件；装备槽不占背包格；金币不占背包格。
- `GetInventory(player)` 懒创建，未显式注册的玩家也会获得默认 20 格背包。

### 2.3 PlayerSoldItem（出售池条目）

```csharp
[System.Serializable]
public class PlayerSoldItem
{
    public GameItem item;      // 出售的物品实例
    public PlayerMove seller;  // 卖家
    public float listedTime;   // 上架时间（Time.time，仅信息展示用）
}
```

规则：

- 上架不限时，不自动过期。
- 出售池无数量上限。
- 买家不能购买自己上架的商品。

## 三、公开 API

### 3.1 容量与查询

```csharp
bool TryAddItem(GameItem item, PlayerMove player);
bool CanAddItem(GameItem item, PlayerMove player);
int GetBackpackCapacity(PlayerMove player);
int GetBackpackCount(PlayerMove player);
List<GameItem> GetPlayerBackpack(PlayerMove player);        // 只读使用
Dictionary<EquipmentSlotType, GameItem> GetEquipped(PlayerMove player); // 只读使用
int GetGold(PlayerMove player);
```

`TryAddItem` 规则：

- `item == null` 或 `player == null`：返回 false。
- 货币：`goldAmount > 0` 时直接加金币并返回 true；`goldAmount <= 0` 返回 false，不占格。
- 装备：目标槽位为空时自动装备，不占背包格，返回 true；槽位已占用且可合成时不占格；否则入背包，占 1 格。
- 消耗品/任务物品：入背包，占 1 格。
- 背包已满且需要占格：返回 false，不产生任何修改，并触发 `OnBackpackFull`。
- 成功后触发一次 `OnInventoryChanged`。

`CanAddItem` 与 `TryAddItem` 容量规则一致，但只做判断，不修改状态。

### 3.2 金币

```csharp
void AddGold(int amount, PlayerMove player);
bool SpendGold(int amount, PlayerMove player);
```

规则：

- `AddGold`：`amount > 0` 才生效，成功后触发事件。
- `SpendGold`：`amount <= 0` 返回 false；金币不足返回 false；成功扣除并触发事件。

### 3.3 使用消耗品

```csharp
bool UseConsumable(GameItem item, PlayerMove player);
bool UseConsumable(GameItem item, PlayerMove giver, PlayerMove target);
```

规则：

- `item` 必须是 `giver` 背包内的原始实例，否则返回 false。
- 只有 `itemType == Consumable` 且 `healAmount > 0` 可执行。
- 成功：从背包移除、对目标 `Heal(healAmount)`、触发事件。
- 目标已满血也允许执行（治疗被 `Health` 上限截断），是否省药由 UI 决定。

### 3.4 出售与出售池

```csharp
bool SellItem(GameItem item, PlayerMove player);
int GetSellPrice(GameItem item);
IReadOnlyList<PlayerSoldItem> GetSoldItems(PlayerMove viewer);
bool BuySoldItem(PlayerSoldItem entry, PlayerMove buyer);
bool CancelListing(PlayerSoldItem entry, PlayerMove seller);
```

`SellItem` 规则：

- `item` 必须在 `player` 的背包内；装备栏物品不可直接出售，需先 `Unequip`。
- 售价由 `SellPriceTable` 配置资产按稀有度查询；价格 <= 0 时不可出售。
- `definition.shopPrice` 是 NPC 商城购买价，不是玩家出售价，两者不要混用。
- 成功：移除物品、加金币、加入 `soldItems`、触发事件。
- 出售后金币即时到账；买家后续购买时金币归系统，卖家不二次结算。

`GetSoldItems` 规则：

- 返回全部未失效条目；`viewer != null` 时过滤掉卖家自己的商品。
- 出售池无上限、不限时，不做分页（本期）。

`BuySoldItem` 规则：

- `entry` 必须仍在池中；买家不能买自己的商品。
- 买家金币足够，且 `CanAddItem` 成功，才会扣钱、移除条目、入包。
- 任一条件失败：返回 false，不扣钱、不移除、不入包。
- 成功后触发一次事件。

`CancelListing` 规则：

- 仅卖家本人可下架；物品返还背包；背包满则返回 false 并触发 `OnBackpackFull`。
- 成功下架后触发事件。

### 3.5 销毁

```csharp
bool DestroyItem(GameItem item, PlayerMove player);
```

规则：

- `item` 必须在背包内；装备栏物品不可直接销毁，需先 `Unequip`。
- 成功：从背包移除，不给金币，永久消失，触发事件。
- 数据层不做二次确认，确认框由 UI 负责。

### 3.6 装备卸下

```csharp
bool Unequip(EquipmentSlotType slot, PlayerMove player);
```

规则：

- 槽位有装备且背包有空位才成功；卸下物品进入背包并重算属性。
- 背包满则返回 false 并触发 `OnBackpackFull`。
- 成功后触发事件。

### 3.7 事件

```csharp
public System.Action OnInventoryChanged;
public static event System.Action<PlayerMove> OnBackpackFull;
```

- `OnInventoryChanged`：任何成功写入（入包、金币变化、出售、购买、下架、销毁、卸下）后触发一次。
- 批量操作（死亡掉落、初始化发放）在循环结束后触发一次，避免每格刷新 UI。
- `OnBackpackFull`：满包导致写入失败时触发，供 UI 弹提示；UI 不轮询判断。
- 不做每玩家独立刷新事件，保持全局事件。

### 3.8 初始化

- `InventoryManager` 保持单例 + `DontDestroyOnLoad`。
- `player1 / player2` 优先 Inspector 引用，缺失时 `Start` 自动查找。
- `startingItems` 在 `Start` 发放，每玩家使用独立实例；无起始物品时列表为空即可。

## 四、调用方行为约定

### 背包 UI（BackpackController）

- 显示 `背包 x/y`，数据来自 `GetBackpackCount / GetBackpackCapacity`。
- 每行：Use（消耗品）、Sell、Destroy。
- Sell 按钮按 `GetSellPrice` 显示价格；销毁按钮需二次确认。
- 订阅 `OnInventoryChanged` 刷新，不再手动刷列表。

### 商城 UI（ShopController）

- NPC 商品页：数据来自 `ShopConfig`（`itemDef + priceOverride + stockCount`），购买流程为 `CanAddItem` + `SpendGold` + `TryAddItem`。
- 玩家出售页：数据来自 `GetSoldItems(currentPlayer)`，购买调用 `BuySoldItem`。
- 背包满时购买直接失败并提示。

### 拾取/掉落（DroppedItem）

- 到达/靠近时用 `TryAddItem`；false 时落回地面，不销毁。
- 货币类不检查背包容量。
- 满包提示由 `OnBackpackFull` 驱动，不再依赖 `Debug.Log`。

### 宝箱/怪物直接入包

- 无 3D 模型分支统一改 `TryAddItem`；false 时宝箱物品落回地面或提示玩家清包。
- 怪物无模型掉落失败时不吞物品，至少给出提示。

### 玩家死亡掉落

- 直接从 `Backpack` 倒序移除，不走 `TryAddItem`，不受容量限制。
- 死亡掉落循环结束后触发一次 `OnInventoryChanged`。

## 五、已确认决策

1. 出售上架不限时，不自动过期。
2. 出售池无数量上限。
3. 本期实现 `Unequip` 和 `CancelListing`。
4. 不做每玩家独立刷新事件，保持全局 `OnInventoryChanged`。
5. 出售价稀有度表做成 ScriptableObject 配置资产 `SellPriceTable`。
