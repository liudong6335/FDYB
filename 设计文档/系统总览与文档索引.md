## 三、依赖方向

```text
World / Items / Player
        ↓ 提供 Provider
      Boss
        ↓ 发布事件 / 请求掉落
EventBus / LootDropService
        ↓
Endgame / UI / AI 观察者
```

核心规则：

- Provider 的实现属于提供方系统。
- Boss 只保存消费方所需的最小契约。
- Boss 发布事件后不等待或决定外部系统如何结算。
- Endgame 不反向控制 Boss 的运行时状态，只消费稳定的实体 ID、事件和 Item 状态。

## 四、事件与状态流

### Boss 死亡

```text
BossDead
→ BossDiedEvent
→ ILootDropService 请求必掉恶魔之心
→ DemonHeart 作为掉落物生成
→ Endgame 监听恶魔之心和玩家淘汰
```

### 结盟状态

```text
AllianceStateChanged
→ allianceVersion +1
→ 目标过滤立即更新
→ 活动快照局部刷新
→ 10 秒快照保存版本号
```

### 玩家淘汰

```text
PlayerEliminatedEvent
→ 结束该玩家参与的全部结盟
→ 刷新目标、求生、策略和 AI 可见快照
→ Endgame 决定是否结束对局
```

## 五、文档维护规则

- 任何数值只能有一个权威来源。
- 任何外部规则只能通过接口或事件引用。
- 跨系统事件必须写明发布者、订阅者和稳定 ID。
- 历史快照和 Replay 数据只追加，不回写。
- 机制变化先更新权威文档，再更新索引和关联引用。
