# 任务物品生命周期设计讨论

---

## 一、当前设计的问题

### 1. 物品所有权不合理

`
当前：任务物品由 NPC 上的 QuestCollectionController 管理
      questItemInstance 是 NPC 脚本的字段
      物品归 NPC 所有，但在世界里显示
      物品由 NPC 生成、跟随 NPC 位置变化
      
问题：物品应该属于任务点/世界，而不是属于 NPC
      开发者直觉上会觉得任务物品在世界里比在 NPC 身上合理
`

### 2. NPC 脚本膨胀

`
当前 NPC 挂载的组件：
  - Transform, CapsuleCollider, NavMeshAgent
  - NPCGoddess, Animator, Health, UGUIFloatingHealthBar
  - NPCGoddessMovement x2 (多余的重复)
  - NPCGoddessBehavior, NPCGoddessHealing
  - QuestCollectionController (管理物品生成/销毁)

如果把物品逻辑从 NPC 挪走，QuestCollectionController 可以简化甚至移除
`

### 3. 物品出现时机不对

`
当前：游戏开始 -> NPC 走路 -> NPC 进入区域 -> 才生成物品

 -> 玩家看不到远处有个发光的东西
 -> 缺少朝着目标前进的视觉引导
 -> 物品出现瞬间 NPC 就到了，没有距离感
`

---

## 二、方案梳理

### 核心变化

`
旧行为：
  游戏开始 -> [物品不可见]
           -> NPC 进入区域 -> 生成物品 -> NPC 找到 -> 采集 -> 物品消失
           -> NPC 进入下一区域 -> 生成物品 -> ...

新行为：
  游戏开始 -> 区域A 物品已出现在 SpawnPoint (可见)
           -> NPC 走向区域A -> 玩家看到物品在前面
           -> NPC 到达 -> 采集 -> 物品消失 -> 宝箱出现
           -> 区域B 物品立即出现 (可见)
           -> NPC 走向区域B -> 玩家看到下一个目标
           -> ...
`

### 物品生命周期

`
  游戏开始
    -> QuestManager.Init()
         -> 区域A 的物品生成 (随机 SpawnPoint 位置)

  NPC 到达区域A -> 采集完成
    -> 区域A 物品销毁
    -> 宝箱在 NPC 位置生成
    -> 区域B 物品生成 (随机 SpawnPoint 位置)

  NPC 走向区域B (物品已经在远处可见)

  NPC 到达区域B -> 采集完成
    -> 区域B 物品销毁
    -> 宝箱在 NPC 位置生成
    -> 区域C 物品生成
    -> ...

  所有区域完成 -> 所有物品已销毁
`

---

## 三、物品归属方案对比

| 方案 | 物品挂在哪里 | 优点 | 缺点 |
|------|------------|------|------|
| A: QuestManager 统一管理 | QuestManager 维护所有物品实例列表，按区域状态激活/禁用 | 集中控制，逻辑清晰 | QuestManager 职责变重 |
| B: QuestArea 各自管理 | 每个 QuestArea 有物品字段，由 areaChain 事件驱动 | 贴近场景，每个区域自包含 | 需要 QuestArea 引用外部系统的预制体 |
| C: 独立 QuestItemManager | 新增组件管理物品生命周期 | 解耦最彻底 | 多一个文件，多一次组件查找 |

**推荐：方案 A (QuestManager 统一管理)**

理由：
- QuestManager 已经管理区域链和完成状态，加物品生命周期是自然延伸
- 不需要 NPC 组件参与物品生成/销毁
- 可以移除 NPC 上的 QuestCollectionController (或大幅简化)
- 一个管理器能保证区域链和物品链同步

## 四、NPC 的变化

### 采集逻辑依然保留，但归属到哪里？

当前流程：
`
NPC 到达 SpawnPoint -> ReadyToCollect -> QuestCollectionController 开始计时
                                         -> 受击回退
                                         -> 完成 -> 通知 NPC
`

如果物品归 QuestManager 管：
`
NPC 到达 SpawnPoint -> ReadyToCollect -> 谁来计时？

选项 1：QuestCollectionController 保留，但只负责检测到达 + 计时
         物品生命周期由 QuestManager 控制
         
选项 2：NPCGoddessMovement 直接处理简单的计时逻辑
         移除 QuestCollectionController，减少一个组件
`

**建议：QuestCollectionController 精简**

保留 QuestCollectionController 但只做两件事：
1. 检测 NPC 到达物品位置 (listen to OnReadyToCollect)
2. 管理采集计时 (2.5s + 受击回退)

**移除** 以下职责 (交给 QuestManager)：
- 物品生成/销毁 (SpawnQuestItemAt / DestroyQuestItem)
- 宝箱生成 (交给 QuestManager 事件)
- 进度条 UI 保留 (采集时在 NPC 头顶显示)

---

## 五、总结：新流程

`
游戏开始
  -> QuestManager.Init()
       -> 激活区域A 的任务物品 (随机 SpawnPoint)
       -> 激活区域A 的怪物 (配置的等级/数量)
       -> 物品在世界中可见

NPC 进入区域A
  -> 触发 QuestManager.EnterArea(Area_A)
       -> QuestCollectionController 监听 OnReadyToCollect

NPC 到达物品位置 -> ReadyToCollect
  -> QuestCollectionController 开始 2.5s 计时
       -> 受击 -> 回退 0.5s
       -> 完成 -> NPC.NotifyCollectionComplete()

QuestManager.OnCollectionComplete(Area_A)
  -> 区域A 物品销毁
  -> 宝箱在 NPC 位置生成
  -> (可选) 区域A 怪物停止生成
  -> 区域B 物品激活
       -> 物品出现在区域B 的随机 SpawnPoint (现在可见)

NPC 走向区域B
  -> 玩家看到物品已经在远处 -> 有目标感
  -> 重复采集流程
`

## 六、待确认问题

1. QuestCollectionController 保留还是移除？
   - 保留简化版 (只做计时+受击检测)
   - 物品生成/销毁交给 QuestManager
   - 保留进度条 UI (采集时在 NPC 头顶显示)

2. 第一区域物品在游戏开始时生成还是等 NPC 走动后再生成？
   - 建议：游戏开始时立即生成
   - NPC 起点就在区域A 附近，玩家一开始就能看到
   - 有远处有个东西等着我们的引导感

3. 物品可见但不标记具体位置，还是直接在高亮显示？
   - 按设计：物品在 SpawnPoint 位置，自然可见
   - 玩家可以自己发现它，也可以跟着 NPC 走

4. 区域A 完成，区域B 物品出现时，是否需要动画/特效？
   - 建议：简单闪现效果
   - 避免突兀出现
