# 《分道扬镳》核心机制设计文档

> 版本：v1.1（补充克制的压制实现、玩家击杀计入进度与死亡规则依赖）
> 定位：1v1 海岛策略竞技，合作 → 竞争 → 对立
> 核心体验：**被迫合作，到必然对立；每一次发育选择，都在赌对手的选择**

---

## 一、设计总纲

### 1.1 一句话核心

> **你杀的每一只怪，都在让你们俩要打的 Boss 变得更强、醒得更早。你停，他可能不停；他停，你却不敢信。**

这不是"队友背刺"的剧情，而是**由资源机制本身制造的囚徒困境**。

### 1.2 设计原则

| 原则 | 含义 |
|------|------|
| **Boss 是唯一胜负目标** | 一切机制（塔、装备、杀怪）最终服务于"打 Boss"；不设立与 Boss 无关的独立胜负条件 |
| **信息对称，而非猜谜** | 关键进度（杀怪数量、Boss 苏醒）对双方公开；博弈来自"明知该合作却不敢先合作"，不是信息不对称 |
| **发育线可被破坏** | 装备线强化"人"，塔线强化"阵地"；两条线最终都指向 Boss 战，且都可被对手针对 |
| **资源单向流动** | 建了就是建了，被毁即消失，无回收、无返还、无退款 |
| **机制制造戏剧，不写脚本** | 信任、背叛、欺骗全部由规则和信息公开自然涌现，不需要剧情事件 |

### 1.3 整局节奏（25 分钟）

```
0 ───── 3 分钟   ：岛中岛守点（强制合作，共同目标）
3 ───── 10 分钟  ：自由探索与双路线发育（装备线 + 塔线）
10 ──── 15 分钟  ：精英怪与杀怪加速期（囚徒困境主体阶段）
15 ──── 22 分钟  ：Boss 苏醒 + 决战准备（拆塔 / 骚扰 / 抢位置）
22 ──── 25 分钟  ：Boss 决战 + 恶魔之心交付
```

## 二、囚徒困境引擎（核心系统）

### 2.1 机制概述

> **双方合计杀怪数量，决定 Boss 的苏醒时间与形态强度。**

- 击杀数量按**双方合计**计算（你的击杀 + 对手的击杀），包含怪物与玩家；玩家击杀的进度权重高于普通怪（初版建议 3-5 倍，待实测）
- 按**单位时间内**的数量分档
- 超过临界值 → Boss **立即跳档苏醒**
- 超出比例越高 → Boss **形态越强**
- 三档均未超过 → Boss **按正常时间苏醒，形态正常**

### 2.2 三档分档（以 10 分钟为例）

| 10 分钟内合计杀怪数 | Boss 形态 | 苏醒时间 |
|---------------------|-----------|----------|
| 0 – 50 | 正常 Boss | 正常时间（如第 15 分钟） |
| 50 – 60 | 普通 Boss | 第 12 分钟（提前） |
| 60 – 100 | 升级版 Boss | 第 10 分钟（大幅提前） |
| 100+ | 暴走 Boss | 第 8 分钟（极度提前） |

> **规则：数量落在哪个区间，Boss 即为该形态，并在对应档位时间苏醒。**
> 具体数值（时间、数量、属性倍率）为初版建议，**需实测平衡**。

### 2.3 为什么这是囚徒困境

| | 对手杀怪（快） | 对手不杀（慢） |
|---|---|---|
| **你杀怪（快）** | Boss 极强且提前醒，双方硬碰硬 | Boss 提前醒，你战力高对手战力低，你占优 |
| **你不杀（慢）** | Boss 提前醒，你战力低对手战力高，你劣势 | Boss 正常醒、强度正常，双方拼操作 |

**双方都知道"都不杀"是最优解，但谁都不敢先停。**

- 你希望对手停，但你不敢停 → 因为你赌他不停
- 结果：双方持续杀怪 → Boss 暴走 → **双输（或极难）**

### 2.4 个人收益 vs 公共代价

- **杀怪收益（个人）**：掉落装备材料、塔合成资源、战力提升
- **杀怪代价（公共）**：Boss 苏醒进度推进、形态升级

**核心张力**：战力提升与 Boss 难度增加的关系必须**微妙**——
- 若战力增益 > Boss 难度增益 → 永远该杀（机制失效）
- 若战力增益 < Boss 难度增益 → 永远不该杀（机制失效）
- **设计目标**：让"该不该杀"在**不同局势下答案不同**，且依赖对对手的判断

### 2.5 克制的实现方式：压制，而非奖励

- **克制没有任何奖励**：不设置停手奖励、封印进度或资源补偿。是否克制本身就是核心决战，奖励克制等于提前替玩家做决定。
- **想"克制发育"的玩家，手段是对手压制，而不是自我停手**：主动追杀对手、压低血量，逼其撤退回血，使其无法或不敢继续刷怪。
- **打残但不打死**：击杀对手同样会大幅推进 Boss 苏醒进度，且幸存者要独自面对更强 Boss，大概率双输。
- **击杀对手是可选的背叛手段**：收益是对手出局、独占发育与 Boss 战；代价是共同威胁大幅推进。
- **死亡规则依赖**：要让"击杀推 Boss"成立，玩家死亡不能再立即判负。建议改为死亡者出局（失去参与权与胜负资格）、对局继续到 Boss 战结束；若幸存者无法单独击杀 Boss 或交付恶魔之心，仍可能双输。（与总览 1.4"玩家死亡=失败"冲突，需统一口径。）

## 三、临界点 UI 与信息规则

### 3.1 UI 设计原则

> **信息完全对称 + 精确数字 + 定期刷新 = 让背叛有窗口、让信任有代价。**

囚徒困境不需要信息不对称。**越是透明，张力越强**——因为玩家知道对手也在做同样的计算。

### 3.2 进度条规则

| 项目 | 设计 |
|------|------|
| 可见性 | 双方均可见，显示精确数字 |
| 内容 | `当前合计杀怪数 / 当前档位临界值` |
| 刷新 | **每 X 秒刷新一次（建议 20–40 秒，时长待实测）** |
| 延迟意义 | 不是"不知道"，而是"来不及反应" |

### 3.3 背叛的时间窗口

- 你在第 N 个周期内杀怪 → 进度条不会立即变化
- 对手看到的是**上一个周期的数字**
- 周期结束后刷新 → **双方同时看到"有人背叛了"**

**这 X 秒就是背叛的窗口**：你看着数字逼近临界值，你知道刷新后会暴露，但你赌对手来不及阻止你。

### 3.4 欺骗的形态

信息透明下，欺骗不是"偷偷做"，而是**"明着做但你来不及反应"**：

- A 提议"都不杀了"
- B 答应，但在下一个刷新周期内继续杀
- 刷新后数字跳档 → A 知道 B 背叛了
- A 的应对：**跟着卷 / 认栽 / 去拆 B 的塔阻止其继续杀**

> **"知道"与"能阻止"是两回事**——这正是信息透明下博弈成立的原因。

### 3.5 玩家协商

UI 让玩家之间**自然产生对话**，无需额外社交系统：

- 一方发信号/语音/文字："别杀了，快到临界点"
- 另一方可以：**合作（停手）/ 背叛（继续杀）/ 假合作（口头答应但继续杀）**

**欺骗是有价值的策略**，但代价是"你也面对更强的 Boss"。

## 四、"双输"的合理性设计

### 4.1 核心问题

> 双方都疯狂杀怪 → Boss 暴走 → 双方都打不过 → **玩家会觉得"我的选择没意义"吗？**

### 4.2 接受的三个条件

1. **因果清晰**：玩家能明确感知"暴走是我们杀太多导致的"（进度条 + 环境提示）
2. **玩家有选择**：克制的一方在暴走局面下**仍有翻盘可能**（哪怕极难）
3. **双输非常态**：是"双方都失误"的极端情况，不是每局发生

### 4.3 暴走 Boss 的设计取向

- 暴走 Boss **不是必输**，而是**极难**
- 操作、塔站位、走位可以弥补部分战力差距
- 克制方（杀得少的一方）**比背叛方面临更好的局面**，但都不是绝对劣势
- 让"我技不如人"可被接受，"我被系统搞了"不可接受

## 五、塔系统（可被破坏的第二条发育线）

### 5.1 设计定位

> **塔主要作为后期 Boss 战的战略资源。它是可被攻击的阵地，形成玩家之间的间接与直接对抗。**

- **装备线**：强化"玩家自身"战力
- **塔线**：强化"Boss 战阵地"战力
- 两条线最终都指向 **打 Boss**

### 5.2 塔类型

| 塔 | 功能 | 备注 |
|----|------|------|
| 攻击塔 | 对 Boss / 怪物输出 | Boss 战主力 |
| 生命塔 | 范围内回血 | 续航 |
| Buff 塔 | 范围内属性强化 | 战略增益 |
| 亲和塔 | 影响恶魔亲和度 | 间接博弈 |

### 5.3 核心规则

| 规则 | 说明 |
|------|------|
| 合成建造 | 图纸 + 石头（独立材料池，不与装备抢宝石） |
| 资源配额 | **全场最多 4 座，保底 2 座**（用总量控制，不逐类设上限） |
| 排他范围 | 40m 内不能重复放置 |
| 不可回收 | 建了即在，被毁即消失；无回收、无返还 |
| 可被攻击 | 对手玩家、怪物、Boss 均可攻击塔 |
| 升级 | 存在但简洁（造出即最终形态，或单次升级不可回收） |

### 5.4 对抗的三种形态

塔"可被攻击"自然产生三种对抗：

| 形态 | 含义 |
|------|------|
| **被动对抗** | 路过看到对手塔 → "要不要拆"的即时决策 |
| **主动对抗** | 专门去找对手塔拆 → 压制其 Boss 战能力 |
| **阵地对抗** | Boss 决战圈附近双方布塔 → 火力对峙 + 互相拆塔 |

### 5.5 "要不要拆塔"的决策权重

- **拆塔耗时**决定了决策重量（数值待实测）
- 耗时太短 → 看到就拆，无决策
- 耗时太长 → 永远不拆，塔成摆设
- **目标**：拆塔是一个"值得想一下"的行为，不是顺手或不可能

### 5.6 与海平面联动

- 低地塔会被淹没 → 鼓励提前转移
- 高地塔是后期可靠阵地
- 时间压力 + 资源赌注

## 六、与整体机制的联动

| 系统 | 联动方式 |
|------|----------|
| **杀怪 → Boss** | 杀怪数量决定 Boss 苏醒与形态（核心引擎） |
| **装备线** | 杀怪的个人收益，与"推高 Boss"形成权衡 |
| **塔线** | Boss 越强 → 塔的阵地价值越高 → 拆塔更有意义 |
| **恶魔亲和** | 影响怪物仇恨与信息感知，作为第三博弈面 |
| **投喂机制** | 引怪、干扰对手发育（鲜肉 / 怪物腐肉 / 感染肉） |
| **海平面** | 时间压力，压缩安全区，迫使向高处集中 |
| **止戈** | 期间攻击塔不攻击玩家，但攻击小怪与 Boss |
| **技能 / 天赋** | 保命技能（隐身 / 加速 / 冰冻）构成职业克制三角 |

## 七、信息设计清单

> 让玩家"感知因果"是机制被理解的关键。

- [ ] 杀怪进度条（精确数字，每 X 秒刷新）
- [ ] 当前 Boss 形态 / 档位提示（UI 或环境变化）
- [ ] 接近临界值的环境预警（天空变色 / 地面震动 / Boss 低吼）
- [ ] 跳档苏醒的明显预警（倒计时、全图提示、应对时间）
- [ ] 塔被攻击 / 被毁的清晰反馈
- [ ] 对手背叛（进度跳档）的即时通知

## 八、开放问题与待办

| 优先级 | 问题 | 方向 |
|--------|------|------|
| P0 | 三档具体时间与杀怪数量 | 实测平衡，以"正常局 60% 到第二档"为目标 |
| P0 | 战力增益 vs Boss 难度增益的曲线 | 确保"杀不杀"在不同局势答案不同 |
| P0 | 进度条刷新周期 X | 20–40 秒区间实测，匹配杀怪速度 |
| P1 | 暴走 Boss 下克制方的翻盘空间 | 确保非必输，操作可弥补 |
| P1 | 拆塔耗时 | 让"拆不拆"成为有意义的决策 |
| P1 | 塔的数量（4 种）是否过多 | 考虑仅保留攻击塔 + 生命塔 |
| P2 | 单局时长与前期节奏 | 避免"全程对峙"僵局 |
| P0 | 玩家击杀对 Boss 进度的权重 | 初版建议 3-5 倍普通怪，需实测；要保证"打残"比"击杀"更可控 |
| P0 | 打残与误杀的边界反馈 | 低血压制需要清晰的濒死警告与伤害控制反馈，避免操作误差变成背叛 |
| P0 | 死亡规则与 Boss 唯一胜负目标 | 玩家死亡改为"出局但对局继续"后，需与总览死亡判负规则统一 |

---

## 九、一句话总结

> **这不是一个"队友会背刺你"的游戏，而是一个"你明知道该停下来，但你看了一眼对手，又继续杀了"的游戏。机制本身就在制造背叛、信任与欺骗——我们只是把进度条公开，然后让他们自己谈。**
