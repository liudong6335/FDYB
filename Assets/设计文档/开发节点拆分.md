# NPC 任务区域系统 — 开发节点拆分

---

## 阶段一：基础数据与配置

**依赖：无（从零搭建）**

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1.1 | 定义区域配置数据结构 | AreaConfig 类：position、radius、spawnPoints[]、monsterLevel、monsterCount |
| 1.2 | 场景中放置区域标记 | 每个区域一个 GameObject + AreaConfig 组件，在 Scene 中用 Gizmos 绘制半径 |
| 1.3 | 定义区域链数据 | 区域列表 + 顺序索引，接入 QuestManager |
| 1.4 | 定义刷出点系统 | 每个区域的 spawnPoints 列表（场景标记点），运行时随机选一个 |

**验证标准：**
- Scene 中能看到每个区域的半径 Gizmos
- 运行时可以遍历区域链
- 刷出点能正确随机选中

---

## 阶段二：QuestManager

**依赖：阶段一**

| 步骤 | 内容 | 产出 |
|------|------|------|
| 2.1 | 创建 QuestManager 单例 | 管理区域链状态：当前区域、完成状态、解锁下一区域 |
| 2.2 | 区域完成条件 | 采集完成 → 标记该区域完成 → 解锁下一区域 |
| 2.3 | 区域事件系统 | onAreaEnter、onAreaComplete、onAllComplete |
| 2.4 | 接入 GameManager 的阶段切换 | 所有区域完成 → 切换到 BossBattle 阶段 |

**验证标准：**
- 运行时可以查询当前区域
- 完成事件能正确传播
- 全部完成后触发 Boss 阶段

---

## 阶段三：NPC 采集系统

**依赖：阶段一**

| 步骤 | 内容 | 产出 |
|------|------|------|
| 3.1 | 创建采集组件 CollectibleItem | 挂在任务物品上，标记可交互、采集完成事件 |
| 3.2 | 采集进度管理器 | NPC 读条：2.5s 基础，受击回退 0.5s |
| 3.3 | 受击检测 | 监听 Health.onDamageTaken → 调用采集进度回退 |
| 3.4 | 采集完成事件 | 触发：物品消失 + 通知 QuestManager + 通知宝箱生成 |
| 3.5 | 采集视觉反馈 | NPC 头顶进度条/光圈/粒子特效（可选） |

**验证标准：**
- NPC 到达刷出点后自动开始读条
- 受击时进度回退 0.5s
- 读条完成后物品消失，事件触发
- 不受击 2.5s 稳定完成

---

## 阶段四：NPC 行为状态机

**依赖：阶段一、阶段二**

| 步骤 | 内容 | 产出 |
|------|------|------|
| 4.1 | 改造 NPCGoddessMovement | 去掉旧的 waypointPath 行走逻辑和 Deviation 系统 |
| 4.2 | 新增状态：导航至区域 | 每 2-3 秒检索目标区域入口，NavMeshAgent 自动导航 |
| 4.3 | 新增状态：搜索物品 | 进入区域后，朝随机刷出点移动 |
| 4.4 | 新增状态：采集 | 到达刷出点 → 调用采集系统 → 等待完成 |
| 4.5 | 新增状态：区域间移动 | 采集完成 → 导航至下一区域 |
| 4.6 | NPC 进入/离开区域检测 | 基于距离检测，触发区域事件 |

**验证标准：**
- NPC 能从当前区域导航到下一区域入口
- 进入区域后自动转向刷出点
- 到达刷出点后自动开始采集
- 采集完成后自动导航至下一区域

---

## 阶段五：区域间救援行为

**依赖：阶段四**

| 步骤 | 内容 | 产出 |
|------|------|------|
| 5.1 | 定义救援范围 | 两区域之间的中间点计算逻辑 |
| 5.2 | 救援触发条件 | 队友血量低于阈值 + NPC 处于转移状态 |
| 5.3 | 救援行为 | NPC 回头至中间点，不踏入上一区域 |
| 5.4 | 救援完成 | 队友脱险 → NPC 掉头继续前往目标区域 |
| 5.5 | 单次转移段限制 | 一个转移段内只触发一次救援 |

**验证标准：**
- 队友低血时 NPC 正确回头
- NPC 不会踏入上一区域范围
- 救援完成后能正确恢复导航
- 不会反复触发

---

## 阶段六：宝箱系统改造

**依赖：阶段三**

| 步骤 | 内容 | 产出 |
|------|------|------|
| 6.1 | 去掉 GameManager 定时刷箱子 | 删除 Timer、chestSpawnPerMinute 等定时逻辑 |
| 6.2 | 新增事件驱动刷箱 | 监听采集完成事件 → 在 NPC 当前位置生成宝箱 |
| 6.3 | 宝箱位置逻辑 | NPC 当前位置半径 2-3 米范围内随机偏移 |
| 6.4 | 宝箱限时逻辑（可选） | 箱子生成后 X 分钟消失，或永久存在 |

**验证标准：**
- 不再有定时刷箱
- 采集完成后宝箱正确生成在 NPC 附近
- 玩家需要回到 NPC 身边才能开箱

---

## 阶段七：怪物系统改造

**依赖：阶段二、阶段四**

| 步骤 | 内容 | 产出 |
|------|------|------|
| 7.1 | 区域怪物配置 | 每个区域关联怪物等级、数量、生成规则 |
| 7.2 | 怪物激活 | NPC 进入区域时激活该区域怪物 |
| 7.3 | 怪物停用 | 区域完成后怪物逐步停止生成 |
| 7.4 | 区域间移动时怪物行为 | 路上怪物密度降低，不触发区域级事件 |

**验证标准：**
- 进入新区域时正确激活怪物
- 离开/完成区域时怪物停止刷新
- 区域间移动时不会激活大片怪物

---

## 阶段八：整合测试

**依赖：全部阶段**

| 步骤 | 内容 |
|------|------|
| 8.1 | 单区域流程测试：进区域 → 找物品 → 采集 → 开箱 |
| 8.2 | 多区域链测试：区域A → 转移 → 区域B → 转移 → 区域C → Boss |
| 8.3 | 采集打断测试：1 只怪 / 2 只怪 / 集火 |
| 8.4 | 救援测试：转移段队友低血 → NPC 回头 → 恢复导航 |
| 8.5 | 边界测试：物品刷在区域边缘、NPC 卡在角落 |
| 8.6 | 奖励测试：箱子刷新位置、拾取、消失 |
| 8.7 | 旧逻辑清理：确认 WaypointPath、Deviation、定时刷箱已被移除 |

## 建议开发顺序

| 批次 | 阶段 | 预估工作量 |
|------|------|-----------|
| **第一批** | 一 + 二（数据层 + 管理器） | ~1-2 天 |
| **第二批** | 三（采集系统，核心玩法） | ~1 天 |
| **第三批** | 四（NPC 状态机，大重构） | ~2-3 天 |
| **第四批** | 五 + 六（救援 + 宝箱） | ~1-2 天 |
| **第五批** | 七（怪物改造） | ~1 天 |
| **第六批** | 八（整合测试 + 清理旧逻辑） | ~1-2 天 |
